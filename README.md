# O!RIVANE — трек «О!дин запрос»

Один запрос превращается в проверяемую поездку: отель, дорога, трансфер, общая стоимость и демонстрационный заказ. Условия хранятся отдельно от диалога; изменение дат или состава гостей пересчитывает план и сохраняет остальные ограничения.

**Статус:** работающий локальный прототип. Все 20 отелей вымышлены; наличие, рейтинги, тарифы, расписания и изображения демонстрационные. Интеграции с Островком нет. Реальные бронирование, оплата и отправка писем не выполняются.

Интерфейс O!RIVANE обновлён по фотографическому референсу: тёмно-синий, шампань, локальная serif-типографика и фото. Главная содержит четыре тематических запроса и шесть районов настоящего демо-каталога; карточка подставляет запрос, кнопка отправляет его агенту. «Мои поездки» возвращает сохранённые в этом браузере подборы и демозаказы через существующий API. Внутренние имена Python-пакета, базы и ключ текущей сессии сохранены для совместимости.

Семь фотографий оптимизированы в WebP (всего около 720 КБ), шрифты WOFF2 размещены локально. Источники и лицензии: [описание изображений и шрифтов](docs/image-credits.md). Hero — атмосферная фотография Каша в Турции, не доступный отель Сочи; это подписано в интерфейсе. Изображения карточек передают атмосферу региона и не являются фотографиями вымышленных гостиниц.

**Демо-видео:** [локальный скринкаст](artifacts/demo.webm) реального сценария записан без озвучки. До сдачи его необходимо разместить на общедоступном хостинге, вставить реальную ссылку в этот раздел и проверить её в инкогнито. Публичной ссылки пока нет; это незакрытый обязательный пункт сдачи. Видео исключено из Git; воспроизводится командой `python scripts/record_demo.py` после установки `python -m playwright install ffmpeg`.

## Быстрый старт

Нужны Docker Engine/Desktop с Compose v2, свободный порт 8080 и интернет при первой сборке для публичных образов и Python-пакетов. Рекомендуется 2 CPU, 2 ГБ RAM и 2 ГБ свободного диска. Модель, GPU и API-ключ не обязательны.

Из выданного организаторами репозитория:

```sh
git clone "$REPO_URL" oplan
cd oplan
docker compose up --build
```

`REPO_URL` — фактический URL репозитория вашей команды в `ostrovok-hackathon-2026`. В исходной рабочей папке не было Git-репозитория или remote; URL команды не выдуман и публикация не выполнялась. Если папка проекта уже открыта, достаточно последней команды.

Открыть **http://localhost:8080**. Приложение и PostgreSQL запускаются вместе; таблицы создаются автоматически. Копирование `.env` и ручное сидирование не нужны. После сборки режим без ключа работает без интернета.

Проверка и остановка:

```sh
curl http://localhost:8080/health
# {"status":"ok"}
docker compose logs app
docker compose down
```

Compose хранит диалоги и заказы в именованном томе PostgreSQL. Обычный `down` их сохраняет. Для удаления данных отдельно предусмотрена стандартная команда `docker compose down --volumes`; она уничтожает локальную историю.

В этой среде Docker и WSL отсутствуют, поэтому **контейнерная сборка и PostgreSQL не проверены исполнением**. Проверены прямой запуск, HTTP, браузер, тесты, доступность фиксированных Docker-образов и получение всех runtime-зависимостей для Linux amd64. Workflow в `.github/workflows/check.yml` собирает и запускает Compose на GitHub Actions; его ещё не запускали удалённо.

### Прямой запуск без Docker

Python 3.11 или новее. Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:DB_URL = "sqlite:///data/oplan.db"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

macOS / Linux:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
DB_URL=sqlite:///data/oplan.db .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Если `.env` не создан, SQLite выбирается автоматически. Явный `DB_URL` в командах также позволяет не использовать Docker-адрес базы из скопированного `.env`. SQLite предназначена для прямого локального запуска; Compose использует PostgreSQL.

## Что показать за 3 минуты

1. Ввести: **«В Сочи с 6 ноября 2026 на неделю вдвоём, до 160 тысяч, с завтраком и прямым перелётом»**. Для более поздней демонстрации заменить дату на будущую.
2. Сравнить три разных отеля: соответствие предпочтениям, минимальная цена, высокий рейтинг. Цена за всех, с дорогой туда и обратно. Посмотреть, что включено и какой есть компромисс.
3. Спросить: **«Сколько стоит мой завтрак?»**. Система покажет разницу минимальных цен при изменении одного условия. Затем можно применить конкретное изменение отдельной кнопкой.
4. Написать: **«На два дня позже, с собакой»**. Дата и допуск питомца изменятся; бюджет, гости, завтрак и транспорт сохранятся. Выбранное предложение сбрасывается, так как его нужно проверить заново.
5. Выбрать отель, проверить маршрут и состав стоимости, ввести тестовые имя/email, подтвердить понимание демонстрационного режима и оформить. Показать номер заказа, скачать JSON, обновить страницу — заказ сохранится.

Дополнительная проверка: «В Прагу…» не подменяется Сочи; «Хочу тёплое море в ноябре» требует согласия на отказ от неподтверждаемого условия; бюджет 1000 ₽ даёт честную пустую выдачу; вопрос о цене пересадки не получает вымышленной суммы.

## Чем отличается от чата и фильтра

- Сообщения меняют типизированное состояние, а не заменяют историю одним ответом. Применяются только распознанные изменения; обязательный вопрос о возрасте ребёнка сохраняется между сообщениями.
- Поиск перебирает реальные объекты одного воспроизводимого демо-каталога, проверяет наличие на каждую ночь, количество номеров и взрослых, питание, отмену, питомцев, бассейн, доступность, расстояние до моря, рейтинг и звёзды.
- Бюджет по умолчанию относится ко всей поездке. Указание «на отель» меняет область проверки, но обязательный сбор за питомца всё равно входит в гостиничную часть; полная стоимость остаётся видимой.
- Перед выбором и оформлением предложение заново строится из каталога. Проверяются не только сумма, но и компоненты цены, даты, гости, тариф, вместимость и время транспорта. Изменённая или устаревшая заявка не оформляется.
- «Цена желания» — сравнение двух минимумов среди допустимых планов в одном каталоге с одним изменённым условием. Это не тарифная надбавка конкретного отеля. Отель может смениться; отдельные экономии нельзя складывать.

Тишина учитывается как предпочтение при ранжировании, не как гарантия. Питание/отмена/бассейн и другие структурированные ограничения проверяются как обязательные; по ним можно явно согласиться на ослабление. Свободный текст не является доказательством характеристики отеля.

## Данные и границы демо

Версия каталога: `sochi-demo-v1`, файл `app/catalog.py`. 20 вымышленных отелей Большого Сочи: Сочи Центр, Адлер, Хоста, Сириус, Дагомыс, Лазаревское. Фиксированные исходные характеристики, сезонные/выходные коэффициенты и детерминированное наличие на каждую ночь. Денежные расчёты — целые рубли, без случайных цен и чисел, созданных моделью. Иллюстрация побережья не является фотографией отеля.

Для транспорта доступны демонстрационные прямой рейс Москва—Сочи и поезд Москва—Адлер, включая обратную дорогу и трансфер в обе стороны. Для другого города система не подставляет Москву. Самостоятельная дорога — явный выбор: её время, билеты/бензин и расходы **не оценены** и не включены. Питание вне тарифа, развлечения, покупки и личные расходы также не включены. План не обещает покрыть все будущие траты путешественника.

Время маршрута — местное московское. Проверяется прошедшее отправление и разрыв до заселения; ранний заезд не обещается бесплатно. Возвратный тариф исключается, если его срок бесплатной отмены уже истёк. Нет живых остатков, реальных договоров с поставщиками или блокировки реальных номеров.

Другие направления, adults-only, спа, подогрев бассейна, вид из номера, «всё включено», визовые и неподтверждаемые погодные требования не объявляются выполненными: требуется уточнение/согласие. Другой каталог можно подключить в модуле `catalog.py`, не меняя HTTP и состояние диалога.

## Понимание запроса и модель

Без ключа работает локальный интерпретатор русских условий: даты/диапазоны, гости и возраст детей, бюджет, дорога, отрицания, район, изменение длительности/даты, характеристики отеля и вопрос о цене компромисса. Это ограниченный словарь и правила, **не локальная LLM**. Интерфейс это сообщает. Он не обеспечивает понимания произвольного текста на уровне языковой модели; сложные и неоднозначные фразы требуют уточнения. Условия всегда видны перед выбором.

Для полноценного языкового извлечения скопировать `.env.example` в `.env` и заполнить:

```dotenv
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=<ваш ключ, только в локальном .env>
LLM_MODEL=<имя доступной модели у выбранного провайдера>
LLM_TIMEOUT=12
```

Поддерживается OpenAI-совместимый `/chat/completions` с JSON output. Модель извлекает только предлагаемые изменения. Выход проверяется Pydantic; точные локально распознанные количества/отрицания имеют приоритет. Модель не создаёт цены и отели, не вызывает оформление. Таймаут, отсутствие ключа, недопустимый JSON или неверная схема приводят к локальному режиму с сообщением пользователю. Реальный запрос к провайдеру в этой среде не проверен; контракты отказа проверены автономными тестами.

Не передавайте реальные персональные данные в демо: введённые имя/email сохраняются в локальной БД, письмо не отправляется. В LLM передаются сообщение и текущие условия поездки; ключ остаётся только на сервере. Отдельных учётных записей нет. Идентификатор сессии — длинный случайный ключ доступа; демо рассчитано на локальный запуск, а не публичную эксплуатацию без дополнительной аутентификации.

## Архитектура

```text
Browser → FastAPI → extract intent → validate/merge requirements
                          ↓                   ↓
                     SQL session      clarify or deterministic search
                                              ↓
                                  eligible plans + explanations
                                              ↓
                               revalidate → simulated order in SQL
```

| Модуль | Ответственность |
| --- | --- |
| `app/models.py` | Ограниченная схема требований и запросов |
| `app/parser.py` | Локальное и опциональное LLM-извлечение изменений |
| `app/catalog.py` | Версионированные демонстрационные объекты |
| `app/search.py` | Совместимость, цены, ранжирование, контрфакты, каноническая валидация |
| `app/service.py` | Состояния агента, вопросы, изменения, сохранённый контекст |
| `app/storage.py` | SQLAlchemy, PostgreSQL/SQLite, атомарная проверка версии и заказа |
| `app/main.py` | HTTP, проверка перед оформлением, идемпотентность, health |
| `static/` | Автономный интерфейс без CDN, сторонних шрифтов и сборщика |

Сессия имеет `revision`; обновление записывается только если версия всё ещё совпадает. Две вкладки не затирают друг друга. Заказ и новое состояние пишутся в одной транзакции; на сессию действует уникальность заказа. Повторный запрос оформления возвращает уже созданный заказ, включая одновременные запросы.

### API/UI

| Путь | Назначение |
| --- | --- |
| `GET /` | Веб-интерфейс |
| `GET /health` | `200 {"status":"ok"}` только при доступной БД |
| `GET /api/config` | Режим понимания, каталог, примеры |
| `POST /api/sessions` | Новый запрос `{ "message": "..." }` |
| `GET /api/sessions/{id}` | Восстановление поездки |
| `POST /api/sessions/{id}/messages` | Изменение естественным языком с `revision` |
| `PATCH /api/sessions/{id}/requirements` | Явное изменение конкретных полей с `revision` |
| `POST /api/sessions/{id}/select` | Выбор текущего `plan_id` |
| `POST /api/sessions/{id}/checkout` | Повторная проверка и демозаказ |
| `GET /docs`, `/openapi.json` | OpenAPI-контракт для разработчиков; `/docs` перенаправляет на JSON, внешние CDN не нужны |

Тестовый логин не требуется. Полные форматы приведены в `docs/api-contract.md` и OpenAPI. Сервер ограничивает размер сообщения и тела; тексты выводятся через безопасные DOM-узлы. CSP запрещает внешний исполняемый код на основном интерфейсе.

### Переменные окружения

| Имя | По умолчанию | Значение |
| --- | --- | --- |
| `APP_PORT` | `8080` | Документирует фиксированный порт контейнера; официальный проброс всегда `8080:8080` |
| `DB_URL` | PostgreSQL из Compose; SQLite без `.env` | SQLAlchemy URL; `postgres://` и `postgresql://` нормализуются к psycopg |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | OpenAI-совместимый провайдер |
| `LLM_API_KEY` | пусто | Ключ только на сервере |
| `LLM_MODEL` | пусто | Модель; без неё используется локальный режим |
| `LLM_TIMEOUT` | `12` | Ограничение ожидания модели, секунды |
| `LOG_LEVEL` | `INFO` | Логи в stdout/stderr |

Все зависимости закреплены в `requirements.txt`, инструменты проверки — в `requirements-dev.txt`. Базовые образы фиксированы; образ приложения многоэтапный, runtime без тестов/компиляторов, процесс UID/GID 10001. PostgreSQL ожидается через `depends_on: service_healthy`. Тяжёлых моделей в Git нет.

## Проверка

После создания `.venv`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app tests scripts
node --check static/app.js
.\.venv\Scripts\python.exe scripts/evaluate.py
.\.venv\Scripts\python.exe tests/frontend_verify.py
.\.venv\Scripts\python.exe tests/rivane_verify.py
```

На Linux/macOS заменить путь к Python на `.venv/bin/python`. `pytest` использует изолированные временные SQLite-БД; реальный провайдер не вызывается. Browser-тест и `evaluate.py` требуют работающий сервис на 8080; можно переопределить адрес `OPLAN_TEST_URL`/аргументом `--url`.

Браузерный тест использует установленный Chrome/Chromium или `OPLAN_CHROME_PATH`. Если браузера нет, перед запуском проверки выполнить `python -m playwright install chromium`. Он проверяет desktop/mobile, изменение условий, минимальные цены, устаревшую версию, заказ, восстановление, скачивание, вопросы, пустую выдачу, ошибку сети и безопасный вывод HTML. Скриншоты сохраняются в `artifacts/ui-*.png`.

`tests/rivane_verify.py` дополнительно проверяет ширины 1440/768/390, загрузку фотографий/шрифтов, карточки районов, настоящий подбор Хосты, мобильную навигацию, возврат сохранённой поездки, закрытие диалога клавишей Escape и защиту от запоздавшего ответа после закрытия. Скриншоты нового дизайна — `artifacts/rivane/`.

`scripts/evaluate.py` прогоняет 12 воспроизводимых HTTP-сценариев, включая отказы и уточнения, и оформляет заказ для каждого допустимого случая. Результат — `artifacts/evaluation.json` с количеством успехов и задержками. Это небольшой авторский набор, а не оценка понимания всего русского языка. Фактические результаты проверки указаны в `docs/verification.md`.
