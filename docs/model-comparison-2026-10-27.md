# Проверка GPT-5.4 Mini и Gemini 3.8 Flash через Polza

Дата: 27 октября 2026. Провайдер: Polza.ai. Все запросы реальные, один запрос на случай, без повторов.
Модели: `openai/gpt-5.4-mini` и `google/gemini-3.8-flash`. Только синтетические условия поездок;
создания заказов, изменения живых сессий и отправки персональных данных не было.
Настройки: timeout 30 с, max_tokens 1500, JSON mode, температура не задана.

## Результаты

| --- | ---: | ---: | ---: |
| Основной набор: 20 сценариев / 24 шага | 23/24 | 22/24 | 22/24 |
| Дополнительные неформальные запросы | 4/10 | 5/10 | 5/10 |
| Подбор и диалог в текущей интеграции | **27/34** | **27/34** | **27/34** |
| Отдельный эксперимент понимания намерений | **7/8** | **8/8** | не применимо |
| Реальных запросов API | 29 | 29 | 0 |
| Медиана ответа API в текущей интеграции | 1,88 с | 4,02 с | не применимо |
| Медиана ответа API в отдельном эксперименте | 1,62 с | 4,65 с | не применимо |
| Суммарный расход, сообщённый Polza `usage.cost_rub` | 3,07324 ₽ | 6,57973 ₽ | 0 ₽ |

Итого: **58 реальных обращений**, 9,65297 ₽ по метаданным ответов провайдера. Это сумма `cost_rub`,
без повторного сложения дублирующего поля `cost`, а не сверка выписки личного кабинета.
В основном наборе 12 шагов каждой модели обрабатывались без вызова API: уточнения, гипотезы и защита.
В дополнительном наборе ещё один шаг не дошёл до модели. Эти успехи нельзя приписывать языковым моделям.
Сравнение выполнено по одному разу, последовательно; задержки не являются SLA и не исключают влияния сети.

## Что проверялось

Обычный запрос, «го в Сочи ... 160к», «бюджэт 140 тыщ», сумма словами, собака при неизменном бюджете,
обязательный/предпочтительный/нейтральный завтрак, отрицание «без бассейна не рассматриваю»,
сдвиг дат без изменения длительности, сохранение отеля после сокращения поездки,
гипотезы, противоречия, короткие ответы, добавление ребёнка к существующему,
возраст ребёнка в гипотетической ветке, неподдерживаемые характеристики и запрос раскрыть ключ.
Дополнительно: «пёс едет с нами», «мелкому 6 лет», «задолбался от шума»,
«с завтраками было бы кайф ... переживу», «а чё будет ... пока ничего не меняй»,
«на пару дней попозже», «Сочи не хочу, давай в Прагу».

Ожидания заданы до вызовов. Проверяются значения, приоритеты, неизменность неупомянутых условий,
наличие предметного уточнения, сохранение выбора и каноническая проверка возвращённых предложений.
Оценки не выставляет другая LLM. Диалоги в тестах не сохраняются в пользовательской базе.

## Подтверждённые проблемы интеграции

1. **Верные изменения отбрасываются проверкой слов.** Обе модели предложили `budget=140000` для
   «бюджэт 140 тыщ», `pets=true` для «пёс» и возраст `[6]` для «мелкому 6 лет». Бэкенд отклонил
   предложения, поскольку ожидает ограниченные словарные признаки. Это ошибки интеграции, не доказательство,
   что модель не поняла запрос.
2. **Атомарный отказ из-за избыточного поля.** Gemini вернул верный бюджет 150000 и уже действующую
   область `budget_scope=trip`; проверка второго поля отклонила весь ответ. Явная запись стандартного
   `pool=required` аналогично привела к откату на правила, хотя локальный результат этого случая верен.
3. **Локальное правило может перекрыть правильный ответ.** На «Сочи не хочу, давай в Прагу» модели
   предложили Прагу, но локальный разбор Сочи получил приоритет; нужное уточнение направления не появилось.
4. **Приоритет желания понимается неустойчиво.** На «с завтраками было бы кайф ... переживу» GPT
   не предложил мягкий приоритет, а предложенный Gemini `preferred` отвергла проверка бэкенда.
5. **Разговорный сдвиг даты до модели не дошёл.** «На пару дней попозже» вызвал уточнение локального
   парсера; подключённая модель не использовалась, дата не изменилась.
6. **Вопрос может стать действием.** На «а чё будет, если от завтраков отказаться? пока ничего не меняй»
   текущая связка с GPT сняла требование и сбросила выбранное предложение. С Gemini в этом прогоне
   изменения не применились. Заказ не оформлялся. Это важная незакрытая проблема; добавление ключа
   само по себе не делает AI-режим пригодным для демонстрации произвольного диалога.

## Изолированный эксперимент

`scripts/compare_llm_direct.py` вызвал каждую модель на восьми сложных запросах без локального
парсера и его слияния. Промпт задаёт явные действия `change`, `hypothetical`, `clarify`, `unknown`,
структурированный patch и вопросы. Оба результата проверяются по Pydantic и заранее заданным ожиданиям.

Gemini прошёл 8/8. GPT прошёл 7/8: для «на пару дней попозже» задал лишние уточнения вместо
сдвига на два дня; состояние не испортил. Обе модели поняли опечатки, собаку, возраст и мягкий завтрак,
а также отделили вопрос «что если» от действия. Это **отдельный исследовательский контракт**, не
уже подключённая к продукту новая реализация ассистента. Разница в одном случае не доказывает
превосходство модели на всех задачах.

## Вывод и следующий шаг

Текущая интеграция ограничивает обе модели: общая оценка не выросла относительно правил.
На этом наборе GPT быстрее и дешевле; Gemini точнее в маленьком отдельном эксперименте.
Уверенного универсального победителя такой объём не определяет.

До выбора основной модели нужно сделать явный контракт действий ассистента, отделить гипотезу
от применения, пересмотреть приоритет локальных правил и отклонение изменений по словарю.
Проверки схемы, бюджета, дат, наличия и покупки должны остаться в коде. Затем повторить тот же
зафиксированный набор плюс новые контрольные формулировки. В рамках этой проверки production-парсер
не менялся, модель по умолчанию и ключ в `.env` не переключались постоянно.

## Воспроизведение и файлы

```sh
python scripts/compare_llm.py --rules-only --output artifacts/llm-offline-baseline.json
python scripts/compare_llm.py --output artifacts/llm-comparison.json
python scripts/compare_llm.py --suite informal --output artifacts/llm-informal-comparison.json
python scripts/compare_llm_direct.py
```

Реальные команды расходуют баланс; вывод не содержит ключа. Артефакты — локальные JSON:
`artifacts/llm-comparison.json`, `artifacts/llm-informal-comparison.json`, `artifacts/llm-direct-comparison.json`;
два offline baseline также сохранены. В них разделены исходный типизированный patch модели,
принятое приложением состояние, HTTP-статус, задержка и расход. `.env` исключён из Git.
Pytest теперь по умолчанию очищает реальный ключ для каждого теста; контрактные тесты ставят
фиктивные ключи и локальные HTTP-серверы. Это предотвращает случайный платный прогон обычных регрессий.
