# O!RIVANE: агент-консьерж

Сохранены FastAPI, SQLAlchemy, синтетический каталог, revision/CAS и идемпотентный checkout. Провайдер — MultiAI, модель — `deepseek-v4.1-flash`. Новых runtime-зависимостей нет.

## Цикл агента

Обычное изменение проходит прежний `change/hypothetical/clarify/unknown` с валидацией. После поиска модель выбирает важные доказательства для объяснения. Вопросы «почему», «сравни», «подробнее» запускают ограниченный цикл: проверка области запроса → решение модели об инструменте → исполнение backend → выбор моделью доказательств → проверенный ответ.

Разрешённые операции: объяснить, сравнить, получить детали отеля, проверить альтернативы, изменить приоритет выдачи, восстановить условия, выбрать явно указанный вариант, проверить план и подготовить оформление. Короткие однозначные команды и восстановление известного состояния выполняются локально. «Выбери второй вариант» выбирает проверенное предложение; «мне нравится второй» не считается согласием.

Инструмента оплаты или создания заказа у LLM нет. Последний шаг — отдельная форма/endpoint с текущей ревизией, проверенным планом, контактными данными и `accept_demo=true`. Сообщение «оформи» лишь готовит этот шаг.

## Проверяемые объяснения

`app/evidence.py` принимает только канонические предложения и формирует факты с ID, текстом и источником: предложение, поле или вычисление. Разницы цен и расстояний вычисляются целыми значениями backend. Модель выбирает инструмент, фокус, порядок доказательств и полезный вопрос о компромиссе; свободный фактический текст модели не публикуется. Это осознанное ограничение, предотвращающее выдуманные скидки, цены и услуги.

ID действуют внутри текущего набора/пары (`offer_indices`). Неизвестные/повторённые ID отклоняются. Сравнение обязано содержать разницу цен, рассказ об альтернативах — проверенные альтернативы. Компромиссы, неизвестные характеристики, гостиничный охват бюджета и неоценённая самостоятельная дорога не могут исчезнуть по выбору модели. Вопрос об услугах относится по умолчанию к выбранному отелю. Спа, детский клуб и вид из конкретного номера не считаются подтверждёнными.

После изменения условий старое объяснение удаляется. PATCH и чипы сразу получают свежие локальные причины; текстовый диалог может дополнить их AI-композицией. Все гостиницы, остатки, рейтинги, тарифы и транспорт остаются явно демонстрационными.

## Контекст и ранжирование

В БД сохраняются `_initial_values`, `_requirement_history` (до 30 изменений), `_ranking`, `_agent_pending`, `_agent_trace` (до 20 записей). Первоначальный снимок включает показанные значения по умолчанию. Впервые уточнённая неизвестная дата сохраняется как исходная известная дата. Отсутствующая история старой сессии не выдумывается. Восстановление дат не удаляет добавленного питомца или новый бюджет.

Жёсткие ограничения проверяются до сортировки. Основной порядок: число выполненных пожеланий → рейтинг → полная стоимость → расстояние до пляжа → стабильный ID. Денежные значения не смешиваются со score. В стандартном показе сохранены ценовая альтернатива и вариант с высоким рейтингом. По явному запросу можно упорядочить по цене, морю или рейтингу без ослабления условий.

## API, сбои и стоимость

`AGENT_ENABLED=1` включает AI-часть консьержа при наличии ключа. При `0` остаются локальные инструменты и факты; прежний LLM-разбор намерений этим флагом не выключается. Для полного режима без внешних вызовов ключ и модель должны быть пустыми.

Агентный цикл: две стадии, общий дедлайн 35 с, до двух попыток на стадию (не более четырёх вызовов). Повтор — только для 429/502/503/504 или исправления схемы; `Retry-After` ограничен 1 с. Ошибки ключа/баланса/доступа не повторяются. Обычное извлечение и последующее объяснение при стандартных настройках имеют суммарную верхнюю границу около 55 с; обычно существенно быстрее. После отказа извлечения дополнительное объяснение не запускается.

Заблокированные сообщения о секретах не передаются ни планировщику, ни генератору объяснений. Отмена асинхронной задачи закрывает HTTP-запрос. В UI виден статус обработки, повторная отправка блокируется. При сбое остаются проверенные локальные факты с честной пометкой. Логи не содержат ключей, заголовков или сырых ответов провайдера.

## Проверки и запуск

```powershell
python -m pytest -q
python -m ruff check app scripts tests
node --test tests/trip-ui.test.mjs
# Отдельный платный прогон на синтетических данных, без БД и заказов:
python scripts/check_agent.py
```

Тесты: `test_agent_tools.py`, `test_agent_transport.py`, `test_agent_api.py`, `test_concierge_core.py`; браузер: `tests/agent_ui_verify.py`. Реальный результат: `artifacts/agent-live-check.json`. Проверяются история после чтения из БД, восстановление, stale revisions, отсутствие заказа от текстовой команды, checkout, повтор, подмена фактов, ограничения инструментов, ошибки и бюджеты повторов.

Dockerfile/Compose сохранены; новые файлы входят в существующие COPY. Docker/PostgreSQL в этой среде не исполнялись: Engine/Desktop и работоспособная WSL недоступны. Нужна отдельная проверка `docker compose up --build` на машине с Docker. Публичная ссылка на демо-видео и официальный репозиторий команды остаются пунктами подготовки сдачи; тег и отправка не выполнялись.

## Проверенные компромиссы

`app/negotiation.py` исследует до семи веток без изменения поездки. Даты +1/+3 дня, на одну ночь короче и существующие подтверждённые поиском предложения. Пользователь применяет конкретное предложение явным действием; backend проверяет снимок условий, выбранный отель и наличие заново. Отказ ничего не меняет. Источники предпочтений сохраняются отдельно без произвольных весов. Подробные результаты и ограничения: [отчёт](ai-negotiation-review.md).
