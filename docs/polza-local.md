# Polza.ai: локальный запуск с облачной моделью

Приложение и база работают локально, модель вызывается сервером через интернет.
Для жюри нужен действующий ключ Polza с доступом к выбранной модели и достаточным балансом/лимитом.
На компьютере жюри не нужны веса модели, GPU или личная подписка ChatGPT.
Это не автономный офлайн-ИИ: без интернета/рабочего ключа остаётся ограниченный интерпретатор правил.

## Модель

Начальная рекомендация: `openai/gpt-5.4-mini`. Кандидат для сравнения:
`google/gemini-3.8-flash`. Оба ID проверены в каталоге Polza 27.10.2026.
Рекомендация предварительная: сравнение качества, скорости и фактического расхода на диалогах проекта ещё не выполнено.
Модель выбирается одной переменной `LLM_MODEL`; автоматического платного переключения между моделями нет.

Источники: [Polza API](https://github.com/polza-ai/docs/blob/main/api-reference/introduction.mdx),
[GPT-5.4 Mini](https://polza.ai/models/openai/gpt-5.4-mini),
[Gemini 3.8 Flash](https://polza.ai/models/google/gemini-3.8-flash).

## Подготовка команды

1. Скопировать `.env.example` в `.env` (существующий `.env` не перезаписывать).
2. В локальном редакторе заполнить `LLM_API_KEY`. Не отправлять ключ в чат, исходный код или открытый Git.
3. Оставить настройки:

```dotenv
LLM_BASE_URL=https://polza.ai/api/v1
LLM_MODEL=openai/gpt-5.4-mini
LLM_TIMEOUT=30
LLM_MAX_TOKENS=1500
LLM_TEMPERATURE=
```

Пустая температура означает параметр по умолчанию провайдера. Лимит ответа и таймаут ограничивают один запрос;
автоматических повторных платных запросов нет. Возможности JSON и параметры конкретной модели нужно подтвердить настоящим вызовом.

## Запуск у жюри

Получить код и предоставленную командой конфигурацию с ключом. Если организаторы окончательно утвердят `age`,
команда шифрует конфигурацию на их публичный ключ, а проверяющие расшифровывают её в `.env` рядом с Compose.
Публичного получателя и окончательного регламента в проекте пока нет; выдуманный адрес/ключ не используется.
Секретный ключ расшифровки организаторов не должен передаваться команде или попадать в репозиторий.

```sh
docker compose up --build -d
docker compose exec app python -m scripts.check_llm
```

Открыть `http://localhost:8080/`. Compose автоматически читает `.env` для подстановки серверных настроек.
После изменения модели/ключа пересоздать сервис, перезагрузка страницы не перечитывает окружение контейнера:

```sh
docker compose up -d --force-recreate app
```

Для прямого Python-запуска проверка: `.venv\Scripts\python.exe scripts/check_llm.py`.
При скопированном Docker `DB_URL` для прямого запуска нужно явно задать `sqlite:///data/oplan.db`, как описано в README.

Проверка делает **один настоящий запрос** с синтетическим бюджетом через тот же адаптер, что приложение.
Она может расходовать баланс. Код выхода 0 означает валидный ответ API; 1 — отказ/невалидный ответ;
2 — настройки отсутствуют/некорректны. Ключ, полный ответ и персональные данные не печатаются.
Зелёный `/health` подтверждает базу и приложение, **не** работоспособность внешней модели.

## Что передаётся и что проверено

На API передаются пользовательское сообщение и структурированные условия поездки.
Имя/email из формы заказа не включаются в этот запрос. Ключ остаётся в окружении сервера;
браузер обращается только к локальному бэкенду.

Проверены настоящий HTTP-обмен с локальным тестовым сервером, путь `/api/v1/chat/completions`,
заголовок авторизации, JSON, таймаут/настройки и ошибки 401/402/403/404/429/503 без раскрытия секретов.
Polza в этих тестах не вызывается. Реальный платный запрос пока не выполнен: ключ не настроен в рамках этой работы.
Docker здесь недоступен; состав образа и Compose проверены по файлам, исполнение контейнеров не подтверждено.

Текущее применение LLM — извлечение предлагаемых изменений с проверкой по схеме и локальным правилам.
Цена, наличие, поиск и демозаказ вычисляются и проверяются кодом. Это подготовленное подключение,
а не заявление о готовом универсальном AI-ассистенте или доказанном понимании всех формулировок.
