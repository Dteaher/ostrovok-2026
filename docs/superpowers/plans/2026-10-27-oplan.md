# О!План Implementation Plan

> **For agentic workers:** Execute with native implementation and independent scoped parallel work, followed by independent review. The user explicitly authorizes autonomous implementation without intermediate approval.

**Goal:** A complete journey from a free-text travel idea to a persistent simulated order, with deep hotel matching.

**Architecture:** FastAPI serves a dependency-free browser frontend and typed JSON API. Deterministic catalog search and validation own prices and eligibility; an optional OpenAI-compatible model only extracts intent. SQLAlchemy persists sessions and orders, PostgreSQL in Docker and SQLite for direct local execution.

**Tech Stack:** Python 3.11+, FastAPI, Pydantic, SQLAlchemy, PostgreSQL 16, HTML/CSS/JavaScript, pytest, Playwright.

**Spec:** The two official PDFs and full Q&A dated 25.10.2026, extracted in tmp/requirements. Source files remain untouched in Downloads.

## Global Constraints
- Full inspiration → direction → search → comparison → assembly → simulated purchase.

- Strict total budget for all travelers; immutable requirements unless user changes them; revalidation at checkout.
- Root README.md, Dockerfile, docker-compose.yml, .env.example; internal port 8080, 8080:8080 mapping; /health returns {"status":"ok"}; multi-stage non-root image; fixed versions; health-gated dependency startup; stdout logs; automatic schema creation.
- No private registries, committed secrets, real payment, invented inventory integrations, public publishing, or premature submission tag.
- Screencast link and organizer repository are mandatory submission items. If unavailable, report as incomplete, never fabricate.

## Decisions and conflicts
The written track includes transport and transfers, while Q&A 31/37/58 permits hotels only. Keep a full journey and small deterministic transport/transfer module; concentrate depth on rooms, occupancy, board, cancellation, date availability, budget and replanning. Q&A's PostgreSQL example is recommended rather than mandatory; Docker nevertheless includes PostgreSQL and health-gated startup to satisfy the explicit Compose requirement. Offline parsing works without keys and is labeled; configured LLM extraction is validated and cannot create prices or bypass search.

## Review Focus
- Ambiguous or unsupported requests: ask or disclose limitations instead of silently changing destination.
- Replanning: preserve guests, dates, budget and hard constraints not explicitly changed.
- Occupancy and arrival/check-in: no underpriced multi-room trip or impossible schedule.
- Price comparisons: nested feasible sets, minimum versus minimum, nonnegative savings, no additive assumption.
- Stale selections and duplicate checkout: revision guard and idempotent persistent orders.
