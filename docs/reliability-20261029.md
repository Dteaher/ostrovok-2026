Старый scripts/verify_live_agent.py мог принять сохранённый parser_mode от прошлого шага за успех нового ответа. Теперь это связанная цепочка, в которой проверяется ожидаемый patch и сохранность остальных требований; для чтения требуется LLM-объяснение, для изменения — разбор и объяснение. Ожидание отложенного объяснения включено. Fallback и частичный успех явно отделены, ошибка даёт ненулевой код завершения.

Повтор цепочки выявил пропуск явно заданного бюджета 1000 рублей: облачная модель могла вернуть пустое изменение или уточнение. Регрессионные тесты воспроизвели все три случая. Валидатор теперь отвергает такое противоречие однозначной абсолютной команде; существующее локальное распознавание сохраняет точную сумму. Промпт дополнен правилом: доступность проверяет поиск, модель не вправе отбрасывать низкий бюджет. Проверка узкая: вопросы, гипотезы и неоднозначные условия не превращаются автоматически в изменения.

Дополнительные регрессии: успешное восстановление после ConnectError/ConnectTimeout/RemoteProtocolError сохраняет тело запроса; максимум две попытки; отмена не повторяется. Семь тестов проверяют честную классификацию LLM/fallback.
